# 百宸 NDA Playbook（本所红线立场）

> **用途：** `nda-review` skill 的 Step 0 第一加载项。`/mnt/user-data/.deer-flow/playbooks/nda-playbook.md`
> 存在即覆盖 skill 内置的通用标准。
> **红线：** 本文件是本所的**审查立场**，不是法律意见。输出仍为供律师复核的草稿。
> **维护：** 由业务委员会修订；每次修订须记录在 §六 变更表。未列入本文件的条款，
> 一律标【资料不足】并升级主办律师，**不得**按模型常识推断立场。

## 一、三级分流判定标准（GREEN / YELLOW / RED）

判定按**风险项计数**：命中任一 RED 项即整体 RED；无 RED 且命中任一 YELLOW 项为 YELLOW；
全部落在 GREEN 项内为 GREEN。

### RED — 必须主办律师加签 → 合伙人签发

| # | 触发条件 | 理由 |
|---|---|---|
| R1 | 保密期限 > 5 年，或**无限期** | 超出商业合理范围；无限期条款实务上不可接受 |
| R2 | 含**竞业限制 / 排他 / 独家**条款 | 可能触及《劳动合同法》§23-24 及《反垄断法》相关限制 |
| R3 | 违约金 > 合同标的额的 30%，或**固定高额**且与实际损失脱钩 | 存在《民法典》§585 调减风险，且对我方敞口过大 |
| R4 | 保密信息范围**无边界**（如"任何信息，无论口头或书面"且无标记要求） | 义务范围不可控，无法举证抗辩 |
| R5 | 我方为**接收方**且条款单向（只约束接收方，披露方无对等义务） | 权利义务显失公平 |
| R6 | 争议解决约定为**境外法院/境外仲裁**，且标的与境内无实质联系 | 争议成本与执行风险显著上升 |
| R7 | 含**知识产权转让 / 许可**或**残留知识（residuals）**条款 | 超出 NDA 范畴，实质是 IP 处置 |
| R8 | 保密信息包含**个人信息**，但未约定处理者义务与跨境传输合规 | 触碰《个人信息保护法》§21/§38 |

### YELLOW — 逐条 redline + 主办律师复核

| # | 触发条件 |
|---|---|
| Y1 | 保密期限 3–5 年（含 5 年） |
| Y2 | 例外情形缺失或不完整（未涵盖：已公开、合法独立获得、独立开发、法定披露） |
| Y3 | 未约定**返还 / 销毁**义务或约定期限不明确 |
| Y4 | 未约定**通知义务**（被要求披露时的通知与协助抗辩） |
| Y5 | 违约责任笼统（"赔偿一切损失"），无上限亦无计算方式 |
| Y6 | 保密信息定义依赖"标记（marking）"，但未约定口头信息的追认期限 |
| Y7 | 我方为披露方，但未取得对等的保密承诺 |
| Y8 | 适用法律为境外法，但未排除冲突法规则 |

### GREEN — 快速通道（批量审查表 + 微调建议，不强制加签）

| # | 条件 |
|---|---|
| G1 | 双方互为披露方/接收方（mutual），义务对称 |
| G2 | 保密期限 ≤ 3 年 |
| G3 | 保密信息以书面标记或书面确认（≤30 日）为准 |
| G4 | 例外情形完整涵盖四类法定例外 |
| G5 | 违约金以实际损失为限，或设有合理上限 |
| G6 | 适用法律为中华人民共和国法律，争议解决为境内仲裁/法院 |
| G7 | 无竞业、无排他、无 IP 转让、无 residuals |

## 二、核心条款审查清单（逐条，不做取舍）

| 条款 | 审查要点 | 本所立场 |
|---|---|---|
| 保密信息定义与范围 | 是否要求标记？口头信息追认期限？是否排除已知信息？ | 要求书面标记或 30 日内书面确认；范围须可界定 |
| 保密义务范围 | 使用限制、复制限制、内部知情人范围 | 限定"为评估合作之目的"；内部披露限于 need-to-know |
| 保密期限 | 固定期限 / 无限期 / 终止后存续 | ≤3 年（GREEN）；3–5 年（YELLOW）；>5 年或无限期（RED） |
| 例外情形 | 已公开 / 合法获得 / 独立开发 / 法定披露 | 四类**必须全部**具备；缺一即 YELLOW |
| 知识产权 | 归属、许可、residuals | NDA 内**不得**约定 IP 转让或许可；出现即 RED |
| 竞业 / 排他 | 是否存在、范围、期限 | **一律不接受**；出现即 RED |
| 违约责任 | 违约金数额、损失计算、上限 | 以实际损失为限；固定高额即 RED |
| 争议解决与管辖 | 法院 / 仲裁、地点、语言 | 优先境内；境外且无实质联系即 RED |
| 返还 / 销毁 | 义务、期限、留档例外 | 应约定；法定留档须明确豁免 |
| 通知条款 | 送达方式、地址、生效 | 须明确；影响违约认定 |
| 适用法律（涉外） | 准据法、冲突法 | 涉外时须排除反致 |
| 签署与生效 | 主体权限、生效条件、期限 | 核对签署人授权 |

## 三、来源分级（每条法律依据必标）

| 级别 | 含义 | 标记 |
|---|---|---|
| **权威核验** | 经 pkulaw / 元典 检索到原文且确认现行有效 | 标条文号 + 链接 |
| **元典辅助** | 元典检索到但未二次核验 | 注明"待核验" |
| **内部模板** | 来自本所既往文本 | 注明模板编号 |
| **模型推断** | **禁止单独作为依据** | 必须标【资料不足】并升级 |

**检索稀薄即停。** 检索不到就写"资料不足"，不得以模型记忆补足条文。

## 四、交付物标准

1. **NDA redline docx**——Word 修订模式，逐条可接受/拒绝，批注引用本 Playbook 条款号（如 `R2`、`Y3`）。
2. **分流判定报告**——GREEN/YELLOW/RED + 命中项编号 + 是否需加签。
3. **审查备忘录**——逐条表：条款号 / 标题 / 风险等级 / 描述 / 修改建议 / 修改后文本 / Playbook 立场引用。
4. **待律师确认事项**——选择题形式，附默认建议。
5. 全文加 **"供律师复核草稿"** 水印 + 免责声明。

**文档生成硬性要求：**
- 一律用 `officecli` 生成/修改 docx，**不要**手拼 OOXML，也不要用 pandoc 产出交付件。
- 交付前必须 `officecli validate` 零错误，且 `officecli view <file> issues` 无溢出/结构问题。
- 修订与批注优先用 `officecli batch`（实测 16x 于逐条 set）。

## 五、红线（与本 Playbook 冲突时的处理）

1. **不替主笔律师定稿**——agent 出 redline，律师逐条接受/拒绝。
2. **不替合伙人签发。**
3. **不无声填补**——检索稀薄即停。
4. **Playbook 未覆盖的条款**——标【资料不足】+ 升级主办律师，不按常识推断。
5. **本文件与 skill 内置标准冲突时，以本文件为准。**
