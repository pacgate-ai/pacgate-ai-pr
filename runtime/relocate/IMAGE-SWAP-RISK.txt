=== 5. Risk assessment ===

  WHAT CHANGES IF WE SWAP:
    - the running container is replaced -> SHORT DOWNTIME for pacgate-api
    - deer-flow: the handbook warns that recreating deer-flow wipes its
      admin user, BUT its state is in the mounted ./data (bind-mounted),
      so data survives. The warning concerns a DIFFERENT scenario.
    - image IDs change, so rollback means re-pinning the old tag

  WHAT WE GAIN: the stack runs the code we just verified builds.

  WHAT WE DO NOT GAIN: correctness. The pulled 0.1.9 image is the one that
  has been running and is the published artifact. The local build is the
  SAME SOURCE rebuilt - swapping adds deployment risk without adding a
  feature or fix.

  RECOMMENDATION: DO NOT SWAP as part of this relocation. The relocation
  goal is "the stack runs from the new path", which is already true and
  verified. Swapping artefacts is a separate, optional deployment that
  should happen when there is a REASON to ship new code - and with its own
  rollback plan.
