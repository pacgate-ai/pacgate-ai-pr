## Two findings that are NOT 0.2.35 regressions

**1. Ollama was running CPU-only, and the documented fix did not apply.**
`ollama ps` showed `100% CPU`. The gate's documented cause (server started before the
ROCm backend unpacked) was wrong here: a clean restart did not help. The real cause is
that this box's only GPU is an **integrated** AMD Radeon 890M, and Ollama drops iGPUs
unless `OLLAMA_IGPU_ENABLE=1`:

    msg="dropping integrated GPU; to enable, set OLLAMA_IGPU_ENABLE=1"
        id=0 library=ROCm compute=gfx1150 name=ROCm0 type=iGPU

With `OLLAMA_IGPU_ENABLE=1` set before starting the Ollama app, the 890M enumerates as
`library=ROCm compute=gfx1150 type=iGPU total="13.1 GiB"` and every runner reports
`100% GPU`. `test-ollama-gpu-residency` then passes. **This must be set in the
machine's environment permanently, or every future boot returns to CPU-only.**

**2. `test-agent-mcp-e2e` is marginal at its 300 s default on this iGPU.**
A single agent turn here takes 120-520 s depending on load, and the gate default
`-TimeoutSec` is 300. Measured run durations from the `deer-flow` logs:

| Run | Duration | Outcome |
| --- | --- | --- |
| `86c9eb39` | 76 s | success |
| `cd52c8c1` | 74 s | success |
| `03fafda0` | 136 s | success |
| `e8fea095` | 80 s | success |
| `c20fe5c5` | **520 s** | success (the gate had already given up at 300 s) |
| `4d135901` | 420 s | error (idle watchdog) |

The 520 s run **succeeded**; the gate had simply timed out first. Standalone with a warm
model the gate passes 9/9 in 121 s. `deer-flow-worker.py` is byte-identical across
`v0.2.32`, `v0.2.35` and `HEAD`, so this is pre-existing capacity behaviour, not
introduced by the sync. Run it standalone, or pass `-TimeoutSec 900`.

An earlier draft of this record blamed `test-model-picker-e2e` for loading
`gemma4-12b-local` (13 GB) and evicting nemotron. That was wrong: the live roster is
`nemotron-bolt-7b-local`, `nemotron-bolt-7b-memory`, `ornith-1.5-9b-local`,
`deepseek-v4.1-flash-cloud`, `glm-5.3-flash-cloud` - there is no `gemma4` entry, so the
picker gate falls back to `models[0]` (nemotron) like every other gate.

## Push status

`git push origin main` was **refused**: `Permission to JZKK720/pacgate-ai-pr.git denied
to pacgate-ai` (HTTP 403). The commit was not rewritten or dropped. It was pushed to the
`fork` remote instead, so it is durable:

    fork/main = 6ffaa0950e27ed29e86fd6a8fa59c23e754e6ba0

`origin/main` remains at `832a591`. Until someone with write access to
`JZKK720/pacgate-ai-pr` fast-forwards it, `main` here is 1 commit ahead of
`origin/main`. That is the state the installer reads: `git rev-list --left-right
--count origin/main...main` returns `0  1` with exit 0, so `install.ps1 -Update`
will report "diverged, not fast-forwardable" and skip the repo refresh rather than
silently claiming the repo is current. The commit is docs-only and reaches no image, so
provenance is unaffected.
